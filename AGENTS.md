Сырой SQL `DELETE FROM conversations` без предварительной очистки `messages` упадёт по FK-констрейнту — это осознанное архитектурное решение (вся работа с этими таблицами и так идёт только через `ConversationRepository`/`MessageRepository`), но стоит иметь в виду при любых будущих прямых SQL-миграциях/очистках. Живая проверка: приложение запущено на профиле `h2`, в логе Hibernate подтверждено создание таблиц и обоих `alter table ... add constraint ... foreign key`.
